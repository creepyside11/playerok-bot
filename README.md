# Playerok Bot

Telegram-бот на aiogram 3 для автоматизации Playerok.

## Возможности

- несколько Playerok-аккаунтов;
- добавление аккаунта по схеме: proxy → cookie или email + код;
- профиль и баланс, создание выплат с расчётом комиссии и история вывода со статусами и маскированными реквизитами;
- уведомления о новых сообщениях, заказах, смене статуса и ошибках;
- автоподтверждение продаж PAID/PENDING → SENT;
- автоответчик по ключевой фразе или *;
- автовыдача постоянного текста или одноразового склада;
- просмотр своих товаров;
- мастер создания и публикации товаров;
- шаблоны товаров: сохранение заполненных параметров, повторное создание черновика и удаление шаблонов;
- каталог выставления товара: категория → игра или поиск игры;
- просмотр Playerok-чатов, пагинация истории и ответы прямо из Telegram;
- Cardinal-подобная система Python-плагинов с переключателем и настройками;
- SQLite для состояния, правил, склада, настроек плагинов и дедупликации событий.

Playerok не предоставляет публично документированный API. Интеграция использует фактические GraphQL-операции сайта и неофициальный клиент PlayerokAPI. Изменения на стороне Playerok могут потребовать обновления.

## Mini App на BotHost

**Emerald Desk** открывается из Telegram и использует те же аккаунты Playerok и ту же базу, что и бот. В приложении есть баланс Playerok, история чатов и текстовые ответы, сделки, создание, публикация и редактирование своих лотов, переключение аккаунтов и уведомления. В разделе «Плагины → ТГ-аккаунты → Управление» доступны склад по странам, привязки лотов и параметры Telegram API.

1. В существующем проекте BotHost выберите репозиторий `creepyside11/playerok-bot`, ветку `main` и точку входа `bot.py`. Сборка использует `Dockerfile` из корня.
2. Включите веб-интерфейс проекта, выберите порт `3000` и назначьте поддомен `playerok-bot.bothost.tech`. Оставьте текущие значения `BOT_TOKEN` и `DATABASE_URL`, чтобы сохранить подключённые аккаунты, плагины и другие данные.
3. Проверьте переменные `PORT=3000` и `MINI_APP_URL=https://playerok-bot.bothost.tech`. Эти же значения используются по умолчанию. BotHost завершает HTTPS на своём прокси, приложение слушает HTTP на `0.0.0.0:3000`.
4. После запуска откройте [проверку доступности](https://playerok-bot.bothost.tech/healthz) и нажмите «Панель продавца» или кнопку «Открыть Mini App» после `/start` в личном чате с ботом. Если кнопка меню не обновилась, назначьте тот же HTTPS-адрес через `/setmenubutton` в BotFather.

Один контейнер запускает Telegram polling, обработчик событий Playerok и HTTP-сервер. Сборка фронтенда и второй процесс не нужны. Аккаунты Playerok добавляются через меню «Аккаунты» в боте. API подтверждает подпись и свежесть Telegram `initData` и проверяет владельца аккаунта при каждом запросе. Значения секретных полей плагинов доступны только для записи нового значения.

В разделе «Баланс → Вывод» бот и Mini App показывают историю выплат и позволяют создать новую заявку на вывод: способ вывода, платёжная система или банк СБП, реквизиты и сумма. Перед отправкой показываются комиссия способа и сумма к получению. Заявка уходит в Playerok только после отдельного подтверждения в интерфейсе.

Реквизиты не сохраняются в базе и не пишутся в логи: в сообщениях бота они удаляются сразу после ввода, в интерфейсе и истории остаются только маска (`•••• 1111`, `+7 ••• ••• -6-7`). Перед самой операцией приложение заново сверяет доступные способы вывода, лимиты и баланс, поэтому устаревшая форма не приведёт к списанию.

Две операции Playerok выполняет только на сайте: привязку и проверку новой карты (в приложении можно выбрать лишь уже привязанную карту) и подтверждение кода из почты, если у аккаунта включена «Защита средств». В этих случаях бот и Mini App показывают ссылку на `https://playerok.com/wallet/withdraw`.

**Выставление лота в Mini App:** откройте «Продажи → Мои лоты → Выставить лот», выберите раздел, категорию и способ получения из каталога Playerok. Заполните цену, название, описание, параметры и комментарий покупателю, добавьте до 10 фотографий (до 10 МБ каждая и 30 МБ суммарно). Мастер создаёт черновик; после этого можно выбрать бесплатное или платное размещение, если тариф доступен. Перед публикацией видны стоимость и остаток баланса, а сервер повторно проверяет условия. Доступна и публикация ранее сохранённых черновиков из карточки лота. Категории, требующие закрытых данных доступа, в этом мастере не поддерживаются.

Для нового SQLite-проекта на BotHost задайте `DATABASE_URL=sqlite+aiosqlite:////app/data/playerok.db` в переменных окружения. Если уже используете PostgreSQL или смонтированную базу SQLite, сохраните её существующий адрес.


## Переменные окружения

Обязательна только:

    BOT_TOKEN=123456789:telegram_bot_token

По умолчанию бот автоматически создаёт SQLite-файл:

    ./playerok.db

При необходимости путь можно изменить:

    DATABASE_URL=sqlite+aiosqlite:////absolute/path/playerok.db

или относительным путём:

    DATABASE_URL=sqlite+aiosqlite:///data/playerok.db

Дополнительно:

    POLL_INTERVAL=6
    LOG_LEVEL=INFO

Cookies, proxy и одноразовый склад шифруются перед сохранением в SQLite. Ключ выводится из BOT_TOKEN, поэтому после смены BOT_TOKEN сохранённые Playerok-сессии нужно подключить заново.

## Запуск

Python 3.11+:

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    export BOT_TOKEN='...'
    python bot.py

Таблицы и файл playerok.db создаются автоматически.

## Docker

Dockerfile использует постоянную SQLite-базу /data/playerok.db. Для сохранения данных между перезапусками подключите volume:

    docker build -t playerok-bot .
    docker run --rm \
      -e BOT_TOKEN='...' \
      -v playerok-data:/data \
      playerok-bot

## Подключение Playerok

1. Откройте Аккаунты → Добавить аккаунт.
2. Укажите proxy в формате ip:port, user:pass@ip:port или ip:port:user:pass. Символ - означает без proxy.
3. Выберите Cookie или Почта + код.
4. Для cookie вставьте строку вида token=...; __ddg5_=....
5. Для email бот вызывает getEmailAuthCode, затем принимает код из письма и проверяет его через checkEmailAuthCode. Полученная сессия сохраняется как cookies.

Для защиты Playerok важно сохранять стабильный IP/proxy и User-Agent сессии.

## Автоматизация

Фоновый worker опрашивает последние исходящие сделки и личные чаты. При первом подключении текущие события становятся baseline и не запускают уведомления или автоматические действия задним числом. Новые события и действия имеют отдельные идемпотентные ключи в SQLite, поэтому рестарты не создают дублей, а временные ошибки автоматических действий допускают повтор.

Для SQLite включены foreign_keys, busy_timeout и WAL, чтобы фоновые записи были устойчивее при параллельных операциях.

Автовыдача привязывается к Item ID. Можно использовать * как правило по умолчанию. Для склада одна непустая строка = одна зашифрованная выдача. Если склад пуст, автоподтверждение соответствующего заказа не выполняется.

## Выставление товара

Мастер получает игру, категории, способы получения, поля и доступные приоритеты прямо через Playerok API. Атрибуты выбираются кнопками, а поля товара запрашиваются по одному с отметкой обязательных полей — JSON вручную вводить не нужно. В черновике можно установить скидку и выбрать бесплатное размещение или платный тариф. Перед подтверждением платной публикации бот показывает сумму списания и расчётный остаток доступного баланса. Черновики доступны в меню «Товары». Мастер запрашивает обязательное сообщение покупателю после покупки и дополнительные поля выбранной категории. Playerok покажет эти данные покупателю в сделке после оплаты.

## Плагины

Плагины лежат в папке `plugins/`. При запуске бот автоматически загружает все `.py` файлы, кроме файлов, начинающихся с `_`.

Каждый плагин объявляет метаданные:

    PLUGIN_META = {
        "id": "my_plugin",
        "name": "My Plugin",
        "version": "1.0.0",
        "author": "Author",
        "description": "Описание",
        "settings": {
            "enabled_feature": {
                "label": "Функция",
                "type": "bool",
                "default": True,
            },
            "text": {
                "label": "Текст",
                "type": "str",
                "default": "hello",
            },
            "limit": {
                "label": "Лимит",
                "type": "int",
                "default": 5,
            },
            "mode": {
                "label": "Режим",
                "type": "choice",
                "choices": ["one", "two"],
                "default": "one",
            },
        },
    }

Поддерживаются async-хуки:

    async def on_message(ctx, chat, message):
        ...

    async def on_deal(ctx, deal):
        ...

Через `ctx` доступны активный Playerok-аккаунт, Playerok client, Telegram bot, фабрика SQLite-сессий и настройки плагина. Удобные методы:

    await ctx.send_chat(chat_id, "Сообщение в Playerok")
    await ctx.notify("Уведомление владельцу в Telegram")

В Telegram откройте **🧩 Плагины** → **📤 Загрузить плагин** и отправьте Python-файл документом. Бот проверит расширение, загрузит модуль и покажет ошибку, если `PLUGIN_META` или код плагина некорректны. После этого выберите плагин: там есть отдельный переключатель включения и кнопка **⚙️ Настройки**. Состояние и настройки сохраняются отдельно для каждого подключённого Playerok-аккаунта.

Плагины выполняют Python-код с правами процесса бота, поэтому загружайте только доверенные файлы. В репозитории есть пример: `plugins/example_echo.py`.

### Каталог товаров

В **📦 Товары → ➕ Выставить товар** доступны два сценария:

- **Категория → игра** — бот собирает категории из каталога Playerok, после выбора показывает подходящие игры.
- **Поиск игры** — поиск через Playerok API по части названия, затем выбор категории.

После этого используется мастер полей, цены, описания, изображения и приоритета публикации.

### Чаты

Раздел **💬 Чаты** показывает личные диалоги и количество непрочитанных сообщений. Внутри чата можно:

- читать последние сообщения;
- листать более старую историю страницами;
- отвечать прямо из Telegram;
- обновлять чат.

Уведомление о новом сообщении также содержит кнопки **Открыть чат** и **Ответить**.
